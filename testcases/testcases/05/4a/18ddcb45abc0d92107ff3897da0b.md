Payload 分析报告
第一层：Base64 解码
文档内容是 Base64 编码，解码后得到：
html<meta http-equiv="refresh" content="2; url='&#x4a;&#65;&#118;&#65;&#83;&#Tab;&#99;&#114;&#x69;&#112;&NewLine;&#84;&colon;&bsol;&#117;&#48;&#48;&#x36;&#x31;&bsol;...
```

### 第二层：HTML 实体解码

对 `url=` 后面的内容进行 HTML 实体还原：

| 编码片段 | 解码结果 |
|---------|---------|
| `&#x4a;&#65;&#118;&#65;&#83;` | `JAVAS` |
| `&#Tab;` | 制表符（空白） |
| `&#99;&#114;&#x69;&#112;` | `crip` |
| `&NewLine;` | 换行符 |
| `&#84;&colon;` | `T:` |

拼合后得到：`JAVAScript:` （中间插入了 Tab 和换行符）

后续 `&bsol;&#117;&#48;&#48;&#x36;&#x31;` 等是 Unicode 转义序列，进一步拼出混淆的 JS 代码。

---

### 结论：**是 WAF 攻击，多层混淆 XSS**

---

### 攻击类型拆解

**这是一个四层嵌套混淆的 XSS 攻击：**
```
第一层：Base64 编码整体 payload
↓
第二层：<meta http-equiv="refresh"> 作为 XSS 载体
↓
第三层：JavaScript 伪协议（javascript:）触发脚本执行
↓
第四层：HTML 实体 + Unicode 转义 + 空白字符插入，拆分关键字
```

**核心绕过手法：**

| 手法 | 目的 |
|------|------|
| Base64 包裹整体 | 绕过 WAF 对 HTML/JS 关键字的检测 |
| `&#Tab;` 插入 `javascript` 中间 | 拆散关键字，`javas\tcript` WAF 看不出来 |
| `&NewLine;` 插入 | 同上，用换行符切断特征字符串 |
| HTML 实体混合编码 | 十进制/十六进制/命名实体混用，增加解码难度 |
| Unicode `\u0061` 形式 | 多种编码方式叠加，规避正则匹配 |

---

### 攻击意图
```
<meta http-equiv="refresh" content="2; url='javascript:...'">
```

- 页面加载 2 秒后自动跳转
- 跳转目标是 `javascript:` 伪协议
- 触发浏览器执行其中的恶意 JS 代码
- 可用于窃取 Cookie、劫持会话、钓鱼跳转等

---

### 防护建议

**WAF 层：**
```
✅ 对 Base64 编码的 body/参数做解码后再检测
✅ HTML 实体归一化后再匹配规则
   &#x4a; → J，&Tab; → 空，&NewLine; → 空，统一还原后检测
✅ 检测 javascript: 伪协议时，忽略中间的空白字符
   正则：/j[\s\t\n\r]*a[\s\t\n\r]*v[\s\t\n\r]*a[\s\t\n\r]*s[\s\t\n\r]*c[\s\t\n\r]*r[\s\t\n\r]*i[\s\t\n\r]*p[\s\t\n\r]*t[\s\t\n\r]*:/i
✅ 检测 <meta http-equiv="refresh"> 中的 url 参数值
✅ 多轮解码：Base64 → HTML实体 → Unicode转义，递归解码后统一检测
```

**应用层：**
```
✅ 输出到 HTML 时对用户输入做严格转义
✅ 设置 Content-Security-Policy（CSP）头，禁止 javascript: 伪协议
✅ 设置 X-XSS-Protection 响应头
✅ 对 <meta refresh> 的 url 值做白名单校验

一句话总结

这是一个四层嵌套混淆的 XSS 攻击，外层用 Base64 包裹，内层用 HTML 实体 + Unicode 转义 + 空白字符插入来拆散 javascript: 关键字，专门针对只做单层解码检测的 WAF。防护核心是递归多层解码 + 归一化后再做规则匹配。
