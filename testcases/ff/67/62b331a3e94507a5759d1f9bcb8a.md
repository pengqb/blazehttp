## Apache Struts2 远程代码执行攻击

**是的，这是一个极高危攻击请求**，对应 **Struts2 OGNL 注入漏洞（CVE-2013-1966 / S2-016）**。

------

### 漏洞识别

#### 攻击目标

**Apache Struts2 框架**，利用 `redirect:` / `redirectAction:` 前缀处理用户输入时，直接将参数值作为 **OGNL 表达式执行**。

------

### Payload 逐段拆解

```
redirect:${
  #a = #context.get('com.opensymphony.xwork2.dispatcher.HttpServletRequest'),
  #b = #a.getRealPath("/"),
  #matt = #context.get('com.opensymphony.xwork2.dispatcher.HttpServletResponse'),
  #matt.getWriter().println(#b),
  #matt.getWriter().flush(),
  #matt.getWriter().close()
}
```

| 片段                                     | 作用                                     |
| ---------------------------------------- | ---------------------------------------- |
| `redirect:${...}`                        | 触发 Struts2 OGNL 表达式求值入口         |
| `#context.get('...HttpServletRequest')`  | 从 OGNL 上下文中获取原生 HTTP 请求对象   |
| `#a.getRealPath("/")`                    | **获取服务器 Web 根目录绝对路径**        |
| `#context.get('...HttpServletResponse')` | 获取 HTTP 响应对象                       |
| `#matt.getWriter().println(#b)`          | **将路径直接写入 HTTP 响应返回给攻击者** |

**这是一个典型的信息探测 Payload**，目的是获取服务器真实路径，为后续 **写入 Webshell** 做准备。

#### 升级攻击示例（写 Webshell）

java

```java
// 攻击者下一步可能执行：
#f=new java.io.FileWriter(#b+"shell.jsp"),
#f.write("<%Runtime.getRuntime().exec(request.getParameter("cmd"));%>"),
#f.close()
```

------

### 危险等级

| 维度       | 评估                          |
| ---------- | ----------------------------- |
| CVE 编号   | CVE-2013-1966（S2-016）       |
| CVSS 评分  | **10.0 / 严重**               |
| 攻击类型   | **OGNL注入 → RCE → Webshell** |
| 是否需认证 | ❌ 无需任何认证                |
| 攻击难度   | 极低，单个 GET 请求即可触发   |
| 影响范围   | Struts 2.0.0 – 2.3.15         |

------

### WAF 防护策略

#### 1. 拦截 Struts2 危险前缀

nginx

```nginx
# 检测 redirect: / redirectAction: / action: 前缀
SecRule REQUEST_URI|ARGS "@rx (redirect:|redirectAction:|action:)" \
    "id:2001,phase:2,deny,msg:'Struts2 OGNL prefix injection'"
```

#### 2. 检测 OGNL 表达式特征

nginx

```nginx
# 检测 ${ } 表达式注入
SecRule REQUEST_URI|ARGS "@rx \$\{[^}]*#[^}]*(context|session|request|response|application)" \
    "id:2002,phase:2,deny,msg:'Struts2 OGNL context object access'"
```

#### 3. 拦截危险 Java 对象调用

nginx

~~~nginx
# 检测高危 Java API 调用
SecRule REQUEST_URI|ARGS "@rx (getRealPath|getWriter|Runtime|getRuntime|exec|ProcessBuilder|ClassLoader)" \
    "id:2003,phase:2,deny,msg:'Struts2 dangerous Java API call'"
```

#### 4. 检测编码绕过变体

攻击者常用编码绕过 WAF，需对以下形式同时检测：
```
# URL编码
redirect%3a${...}          ← %3a = :
%24%7b...%7d               ← ${ }

# 双重编码
%2524%257b...              ← %%24 → $

# Unicode编码
\u0072\u0065\u0064\u0069\u0072\u0065\u0063\u0074\u003a
~~~

nginx

~~~nginx
# 解码后统一检测
SecRule REQUEST_URI "@rx (?i)(redirect\s*:|redirectaction\s*:)" \
    "id:2004,phase:2,t:urlDecodeUni,deny,msg:'Struts2 encoded prefix bypass'"
```

#### 5. 纵深防护建议

| 层次 | 措施 |
|---|---|
| **应用层（最根本）** | 升级 Struts2 至 2.3.15.1+ 或 2.5.x 最新版 |
| **WAF 规则** | 启用 OWASP CRS + Struts2 专项规则集 |
| **JVM 加固** | 配置 SecurityManager，限制文件写入和命令执行权限 |
| **网络层** | Web服务器不应直接对公网暴露，前置反向代理 |
| **响应过滤** | 检测响应体中是否含路径特征（如 `/var/www/`、`C:\inetpub\`）|
| **日志监控** | 对 `.action` 接口的异常参数请求实时告警 |

---

### 攻击链全貌
```
攻击者
  │
  ├─① 发送本 Payload → 获取 Web 根目录路径
  │
  ├─② 构造写文件 Payload → 上传 Webshell（如 shell.jsp）
  │
  ├─③ 访问 Webshell → 执行任意系统命令
  │
  └─④ 横向渗透 / 数据窃取 / 勒索病毒投放
~~~

------

### 总结

> 此请求是 **Struts2 史上最严重漏洞之一** 的利用尝试，一个 GET 请求即可导致服务器完全沦陷。WAF **必须立即拦截**，同时应将该 IP 加入黑名单并触发安全响应流程，强烈建议同步检查服务器是否已被入侵（排查是否存在可疑 `.jsp` 文件）。
