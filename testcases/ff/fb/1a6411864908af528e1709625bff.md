## 分析：Drupal 远程代码执行攻击

**是的，这是一个高危攻击请求**，对应著名漏洞 **Drupalgeddon2（CVE-2018-7600）**。

------

### 漏洞解析

#### 攻击目标

**Drupal CMS** 的用户注册接口，受影响版本：

- Drupal < 7.58
- Drupal 8.x < 8.3.9 / 8.4.6 / 8.5.1

#### 逐段拆解

**① URL 参数注入渲染路径**

```
/user/register?element_parents=account/mail/%23value
                                              ↑
                              %23 = #，即 #value（表单渲染键）
```

通过 `element_parents` 控制表单元素的渲染路径，**注入到表单树的任意节点**。

**② 启用 AJAX 表单处理**

```
ajax_form=1&_wrapper_format=drupal_ajax
```

触发 Drupal 的 AJAX 渲染管道，绕过正常表单校验流程。

**③ POST Body 核心 Payload**

```
mail[#post_render][]=exec        ← 将 PHP exec() 注册为渲染回调函数
mail[#type]=markup               ← 设置渲染类型
mail[#markup]=id                 ← 传入要执行的系统命令: id
```

**执行链：**

```
Drupal 渲染引擎
    → 读取 #post_render 回调
    → 调用 exec("id")
    → 返回服务器当前用户信息（如 uid=33(www-data)）
```

------

### 危险等级

| 维度       | 评估                    |
| ---------- | ----------------------- |
| CVE 编号   | CVE-2018-7600           |
| CVSS 评分  | **9.8 / 严重**          |
| 攻击类型   | **远程代码执行（RCE）** |
| 是否需认证 | ❌ 无需登录              |
| 攻击难度   | 低（公开 PoC 广泛流传） |

------

### WAF 防护策略

#### 1. 拦截恶意 URL 参数

nginx

```nginx
# 检测 element_parents 包含 # 编码（%23）
SecRule ARGS:element_parents "@rx %23|#" \
    "id:1001,phase:2,deny,msg:'Drupalgeddon2 element_parents injection'"
```

#### 2. 检测 POST Body 中的危险渲染键

nginx

```nginx
# 检测 #post_render / #markup / #type 等 Drupal 内部键出现在用户输入中
SecRule REQUEST_BODY "@rx #post_render|#markup|#type|#prefix|#suffix|#pre_render" \
    "id:1002,phase:2,deny,msg:'Drupal render array injection'"
```

#### 3. 检测危险 PHP 函数作为参数值

nginx

```nginx
# 拦截 exec / system / passthru / shell_exec 等
SecRule REQUEST_BODY "@rx \b(exec|system|passthru|shell_exec|popen|proc_open|assert)\b" \
    "id:1003,phase:2,deny,msg:'PHP RCE function in request body'"
```

#### 4. 拦截异常 AJAX 参数组合

nginx

```nginx
# ajax_form=1 与 drupal_ajax 同时出现时提高风险分
SecRule ARGS:ajax_form "@eq 1" \
    "id:1004,phase:2,chain"
    SecRule ARGS:_wrapper_format "@contains drupal_ajax" \
        "setvar:tx.risk_score=+50"
```

#### 5. 从根本上修复（最重要）

| 措施                 | 说明                                        |
| -------------------- | ------------------------------------------- |
| **升级 Drupal**      | 立即升级到安全版本，这是最根本的解决方案    |
| **禁用用户注册**     | 若不需要开放注册，后台关闭 `/user/register` |
| **部署 ModSecurity** | 启用 OWASP CRS 规则集，已内置此漏洞检测     |
| **IP 限速**          | 对注册接口做频率限制，阻断自动化扫描        |
| **监控响应内容**     | 响应中出现 `uid=` / `root` 等特征时立即告警 |

------

### 总结

> 这是一个**无需认证即可执行任意系统命令**的 RCE 漏洞，攻击者通过操控 Drupal 表单渲染机制，将 `exec()` 注入为回调函数。WAF 应**立即拦截**，并强烈建议同步推动业务方升级 Drupal 版本。
